# Historical upstream change assessment

## Current direction

The maintainer superseded this selective-import policy on 2026-10-10. The main goal was to adopt the latest upstream repository as the application/runtime/dependency/build baseline, then preserve and restore OhPiChamber customization. The [rebaseline spec](specs/upstream-rebaseline.md) and its workflow tasks govern that work; OpenCode 2 and newer product features were not excluded merely to preserve 1.x. The source has now been adopted; assembled runtime acceptance is active but blocked, and task 03/W5 source-aware documentation review is queued and has not started.

The investigation below is a pre-adoption record retained for source references, risks, and historical comparison. Its pick/exclude/defer labels describe the earlier decision, not current import instructions. Recheck findings against the upstream revision refreshed at execution time. After the new baseline is verified, remove stale application-version framing from project guidance rather than replacing it with another hard-coded release label.

## Current adopted baseline

The authoritative adopted baseline is upstream `0056bf6a9` (v2.5.2+1, 2026-10-26, 813 commits after `1f9320062`), documented in `.workflow/upstream-refresh-2026-10-27.json`. The refresh reconciles all 4,031 changed paths (2,932 across adoption tasks 01–25, 392 across documentation tasks 26–29, and 707 in 10 approved exclusion buckets) while preserving fork-owned OMP architecture, Host Gateway security boundaries, and private Guest SDK `MessagePort` v2 transports. The current package/workspace baseline is 3.0.0 (mobile 1.13.2) with Node `>=24.14.0`, Bun 1.4.4, oxlint 1.88, and Electron 44; no upstream release number (e.g. 2.5.2) is adopted. Full root frozen install, type-check, lint, root tests (scripts, SDK, UI, agent-contract, agent-service, Electron, Web), dead-code inspection, docs validation, and Linux packaged desktop build passed. Upstream history is linked via an `ours` merge (`git merge -s ours 0056bf6a9`) so that `0056bf6a9` serves as the next synchronization merge-base. Explicit unverified boundaries remain documented: native iOS/Android toolchains and devices, live Docker containment for isolated spaces, and external credentialed tunnel integrations (Tailscale).

## Comparison and limits

Reviewed on 2026-10-10. The fork's metadata remains OpenChamber v1.24.2. Its previous synchronization selectively used upstream v2.1.1, not every commit at that tag.

This assessment compares [v2.1.1 with pinned main](https://github.com/openchamber/openchamber/compare/v2.1.1...78dacb27fee580ec945a828d781cfe39b200b7bd). The input contains 309 commits and 1,925 net changed paths, including upstream review images. [v2.2.0](https://github.com/openchamber/openchamber/releases/tag/v2.2.0) is at `74b79d41eac44ff38790c66f238050936083e0bb`; the pinned main also includes 57 later commits. It is a dated snapshot, not a promise that main will stay there.

Six read-only reviews covered host/CLI, desktop/mobile/Guest SDK, UI state, UI rendering, tooling, and isolated spaces. Findings were reconciled against the fork's scope and local source. No upstream application code, dependency, release metadata, or changelog was applied. No application test or runtime benchmark was run for this assessment. Pick means a recommended future port of the relevant behavior, not a blind whole-commit cherry-pick or a verified local fix.

The [scope hierarchy](omp-migration/scope.md#document-hierarchy) still governs the final OMP product target; the [development record](development.md) owns implementation status. Neither the final engine-retirement goal nor the historical exclusions below requires holding the prerequisite update on the old runtime.

## Additional source-inspection findings

Read-only prerequisite maps of the same pinned source were completed before the maintainer changed the work to a full rebaseline. These findings explain the rejected 1.x selective-port approach; they are not new exclusions or runtime verification:

- Board is an application/host source-control feature spanning GitHub/Linear APIs, shared reference browsing, navigation, composer attachments, and settings/state. Its feature logic did not itself require the newer agent SDK. Recheck the full upstream package closure rather than importing only its view.
- Environment management overlays user/project variables onto Git, terminal, filesystem execution, and agent process startup. Preserve its host execution ownership, secret-safe persistence, worktree-root mapping, and refresh behavior.
- Quake uses Electron global shortcuts, window geometry/restoration, and desktop settings; file-tree moves require host collision/self-nesting rejection, in-flight path rebasing, dirty-editor preservation, and the mid-move tab-switch save follow-up. Neither feature justified an agent-runtime compatibility adapter.
- Guest Shell lifecycle uses the upstream Shell list/output/stop APIs and created/exited/deleted events, with recent-ended state and bridge permissions. Those capabilities were absent from the old runtime. A permanently empty store or imported SDK types alone would not deliver the feature.
- Later isolated spaces couple transfer/quarantine/apply, dispatcher/session/events, host lifecycle, grants/credentials, settings and preview. The newer implementation depends on matching agent/runtime credential and session APIs. Retain gatekeeper-memory credential containment, host-built quarantine/apply, owner-scoped Docker resources, and preview proxy isolation as boundaries requiring fresh evidence.
- Tooling changes include Node 24, matching container image/hardening, TypeScript project references and declaration output, and changed-file verification. Recheck the new scripts and dead-code policy as a complete build contract. The old workspace's non-blocking dead-code setting is an observation, not an instruction to override the new baseline forever.
