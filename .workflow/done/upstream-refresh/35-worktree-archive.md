## Interfaces

### Archive routes

Host, all under `registerGitRoutes` and behind the existing lazy `getGitLibraries()` import:

- `GET /api/git/worktrees/archives?directory=<any checkout of the project>` → 200 `{ archives: Archive[] }`, newest `archivedAt` first. 400 `{ error: 'directory parameter is required' }` without the query.
- `POST /api/git/worktrees/archives?directory=<project>`, body `{ directory: <worktree path>, id, title? }` → 200 `Archive`; `userAction`. Host derives all admitted session IDs.
- `POST /api/git/worktrees/archives/restore?directory=<new checkout>`, body `{ id }` → 200 `{ id, conflicts }`; `userAction`. `directory` is the checkout the caller has already created on the archive's branch (or on the archive's head commit when that branch is gone), exactly as upstream's route and test use it. It is never the project directory and never `Archive.path`.
- `DELETE /api/git/worktrees/archives?directory=<project>`, body `{ id, deleteBranch? }` → 200 `{ id, branchDeleted }`; `userAction`.
- Status policy: 400 for a missing `directory` (query or body), a directory that does not resolve, or an archive id that already exists; 404 `WORKTREE_ARCHIVE_NOT_FOUND`; 409 `WORKTREE_ARCHIVE_IN_PROGRESS`, `WORKTREE_ARCHIVE_NOT_APPLIED` and `WORKTREE_ARCHIVE_PARTIAL` (the fork maps the upstream fall-through explicitly, because the folder is partly deleted and the ref is kept); 409 `RUN_ACTIVE` and `COMMAND_IN_FLIGHT` relayed from the supervisor with its code and the session or lease it names; 501 `{ error: 'Worktree bootstrap storage is not available' }` when the injected `worktreeBootstrapStore.remove` is missing and 501 `{ error: 'Worker lifecycle control is not available' }` when the lease-control hook is missing — both before any git or filesystem change; 503 `SERVICE_UNAVAILABLE` when the Agent Service cannot be reached or does not answer the lease; 500 only for an unexpected local failure. Only the 500 branch logs.
- The route never resolves 200 when the folder was not removed; Host owns session rollback, without a duplicate client rollback.

Git refs remain the sole archive list; record `path` and `sessionIds` are untrusted metadata, never session authority. The public projection distinguishes bound, verified-empty, unverified legacy and ref-changed records.

### Worker lease (Agent Service, internal and SDK-private)

Two private supervisor routes beside `/internal/workers`, reachable only by the Host through its existing `service.request` client, never by the UI or an SDK caller:

```
POST /internal/worktree-leases      { leaseId: <Host-generated UUID>, directory: <absolute path> }
  201 { leaseId, released: [rootSessionId, ...] }
  400 INVALID_REQUEST      the directory is relative or empty, or the lease id is missing or malformed
  409 RUN_ACTIVE           a session worker at that directory has an active run; details { sessionId }
  409 COMMAND_IN_FLIGHT    a worker there is starting, has pending operations or actions, has a
                           running shell job, holds a restart reservation, or has session storage
                           inside the directory; details { sessionId }
  409 COMMAND_IN_FLIGHT    the directory overlaps an existing lease, same path, ancestor or
                           descendant; details { leaseId, directory }
  409 COMMAND_IN_FLIGHT    the supplied lease id already names an active lease; details { leaseId, directory }
DELETE /internal/worktree-leases/:leaseId      -> 204, idempotent
```

Lease record: `{ leaseId, canonicalDirectory, released: string[] }`. A separate pending-acquire entry owns the Host-supplied id only while that request's asynchronous canonicalization is in flight; DELETE cancels that entry, and its acquire must reject rather than install a fence. The entry is removed when the acquire settles, so it is not a tombstone. The id is generated by the Host before POST and the Agent Service never mints it. A DELETE for an unknown id is 204. Leases live in Agent Service memory only. One lease-mutation chain serializes overlap, fence install, worker stop and release; no TTL, persisted marker, reconcile route or replay. `released` names stopped entries for diagnostics (session roots, workspace roots and the usage worker id), not authority for the Host.

Acquire is the release, in this order:

1. Validate that the directory is absolute, synchronously reserve the supplied lease id against duplicate acquires, then canonicalize it (`realpath`, the same convention the Host uses for bootstraps and `removeWorktree` uses at `service.js:5919`). Canonicalization may `await` outside the lease-mutation chain; it does **not** decide overlap. A directory that does not resolve is 400, and the pending id is removed when that acquire settles.
2. Enter the single lease-mutation chain and, in one synchronous block inside it, reject a cancelled pending id, check overlap, install the admission fence and snapshot every `workerEntries` entry whose `input.cwd` is that directory or inside it. No `await` separates the overlap check, fence install and snapshot. The overlap check is the same path as, an ancestor of, or a descendant of an existing lease, answered with 409 `COMMAND_IN_FLIGHT` and `details { leaseId, directory }`; containment is segment-safe (`path.relative` plus `sep`; never a string prefix), matching `isInsideOrSameDirectory` at `service.js:624-627`. The chain is the only place overlap is decided, so two acquires that canonicalized concurrently cannot both pass. A start that spawns during the earlier canonicalization is already in `workerEntries` when the fence is installed, so the snapshot sees it; a start that has not spawned yet reaches `launch`'s pre-spawn check after the fence. The fence, not the per-root `withRoot` lock and not `admit` entry, is the synchronization point; `withRoot` serializes one root only.
3. Stop each snapshotted entry through the per-root `withRoot` serialization, with the guards for its kind. Session entries need the `sessionIsIdle` probe, no starting state, no restart reservation, no pending operations or actions and no running shell jobs, with the same re-checks `evict` performs before it stops. Stateless and usage entries need no starting state, no pending operations or actions, and `stopEntry`; `evict` must not be reused for them because it returns `true` immediately for a non-session entry. A session entry whose `sessionsDirectory` or `sessionFile` is inside the leased directory is refused: removing the folder would delete session storage (the Host default agent directory, `~/.omp/agent`, is outside, but the guard covers a configured one).
4. Prove each stop succeeded by the entry being absent from `workerEntries`, the child having exited, and the worker's process group having exited through `waitForWorkerProcessTree(pid)`. Do **not** use `stopEntry`'s boolean: it returns `child.exitCode === 0`, which is false for a normally SIGTERM-terminated worker. `stopEntry` itself calls `waitForWorkerProcessTree` only when group signalling succeeded, so the lease calls it again. On Windows the helper returns `true` unconditionally; the lease records that limit and does not claim group proof there.
5. Return 201 with the supplied `leaseId` only after every stop has finished. On any refusal, remove the installed fence, create no lease, and return the 409 with the first refusing session. A release call after a failed acquire is safe and idempotent.
6. A refusal can leave earlier idle workers stopped while the caller only unarchives sessions; those sessions reopen cold. There is no pre-probe and no atomic-rollback claim.

Admission: `admit` checks the fence as a fast refusal, and `WorkerRegistry.launch` checks it again at the last synchronous point before `spawn`, with no `await` between the check and the `spawn`. That one check covers `start`, `startStateless` and `startUsage`, including a start already inside `prepareBootstrap`; no pending-start map is required. An in-flight start is therefore either already in `workerEntries` (the acquire snapshot sees it and stops it) or its pre-spawn check sees the fence. Any start or reopen whose `cwd` is inside a leased directory answers 409 `COMMAND_IN_FLIGHT` with `details { leaseId }`.

Release: by the caller-supplied `leaseId`, idempotent, no path required. In the lease-mutation chain, DELETE removes an installed fence and marks any matching pending canonicalization cancelled; the pending entry remains only until that acquire settles, then is removed. A duplicate-id 409 identifies an id this archive did not create and is surfaced without DELETE, so the original owner is not released. The Host calls release in `finally` even if the POST response is lost. `DELETE /internal/workers` semantics are unchanged.

No expiry: there is no `capacityPolicy.worktreeLeaseTimeoutMs` and no "an expired lease stops blocking" criterion. A Host-supervisor restart hold (below), not a timer, keeps a crashed service from admitting a new generation while the Host is still archiving. The owner-death cleanup is `process.once('disconnect', stop)` in `agent-service/src/index.ts` after the secret handshake, beside the existing SIGTERM/SIGINT handlers; a hard-killed Host therefore does not leave the detached service and its unrelated workers running. The IPC disconnect is cleanup, not the fence.

### Host supervisor restart hold

`createAgentServiceSupervisor` exposes `holdRestarts()` and `resumeRestarts()` as a refcount, so two concurrent archives cannot let the first release restart under the second. `holdRestarts` clears a pending `restartTimer`; `scheduleRestart` returns early while held **without consuming `restartAttempts`**; `start(fromRestart === true)` also returns while held. `resumeRestarts` drops one hold and, when the count reaches zero and no child exists, calls the existing `start(true)`; no new timer, no persisted file and no new process. A service crash during the archive therefore spawns no new generation until removal is done and the lease is released, then exactly one generation starts. While the service is alive, unrelated sessions are unaffected except by the path-scoped lease; if it crashes, unrelated sessions are down until resume — the outage a crash already causes, extended by the remaining archive time, with no unrelated worker killed.

Composition: `index.js` builds one lease-control object from `hostAgentRuntime.service` — `archiveWorktree` generates the lease id first, the hook `holdRestarts()` before the `POST /internal/worktree-leases` with that id in the body, and `release(leaseId)` plus `resumeRestarts()` in the same `finally` on every path, including a refused acquire or a lost 201. Holding before acquire closes the window between the service returning a lease and the Host recording anything. No new Host route, timer, durable marker or second lifecycle path is added.

Old-worker proof needs no persistence: acquire returns only after every worker at or inside the path is gone, and the pre-spawn fence makes a new worker there impossible; if the service then dies, no generation exists to start one. A crash after release is an ordinary service restart with the folder already removed.

Residual: if release itself fails against a live, hung service after removal, the in-memory lease blocks that path until the service restarts. Removal has already succeeded, so nothing is executing under it, and the plan does not add a TTL or a retry loop as the fix.

### Archive service

Service (`packages/web/server/lib/git/service.js`):

- `listWorktreeArchives`, `archiveWorktree`, `restoreWorktreeArchive` and `deleteWorktreeArchive` keep Git ref ownership; the existing Host session owner supplies the archive-scoped binding and session operations described below. The Host generates the lease ID before acquire and releases it in `finally`, even after refusal or a lost response.
- Archive ids are `^[A-Za-z0-9_-]{1,80}$`; archive, restore and delete validate the id through the adopted `assertWorktreeArchiveId`/`readWorktreeArchive` path, and list skips a message that is not an archive record. The archive is a snapshot commit of the worktree — every change git does not ignore — under `refs/openchamber/archive/<id>`, whose parent is the commit the branch stood on and whose message is `OpenChamber worktree archive` followed by the JSON record; nothing else records an archive, so the repository is the list.
- Acquire lease and hold restarts; wait for bootstrap; snapshot and write ref; persist Host binding, capture original session states and archive newly active sessions; recheck the complete Host set; remove the checkout; release lease and hold in `finally`.
- On intact failure, Host rolls back only newly archived sessions and compare-deletes the exact ref. Partial removal retains ref and binding and returns `WORKTREE_ARCHIVE_PARTIAL`; Host rolls back only newly archived sessions, preserving previously archived timestamps.
- The primary workspace, a stray directory, a worktree that never finished setup and a second archive of the same path (the upstream `worktreeArchivesInFlight` same-path pre-check) are refused. Overlap with another lease is refused by the lease, not by this local set.
- Restore uses the caller-created checkout, never `record.path`; verifies a complete prospective target fingerprint before applying, and retains the ref until Host-verified session transitions complete. Conflicts stay in the checkout; refusal retains the archive.
- Host fences both source and restore target throughout nonterminal operations, including after claim release or restart; no new Agent Service lease is added for restore.
- Deleting removes the ref and, when asked, the branch — never a branch a checkout uses.

Boundary: `/api/git/worktrees` is already an entry in `REFUSED_ACROSS_BOUNDARY_ROUTES` and the matcher treats entries as prefixes, so `/api/git/worktrees/archives` and `.../restore` are refused across a space boundary without a new rule; the dispatcher test proves both, and `packages/web/server/lib/spaces/DOCUMENTATION.md` lists the archive routes with that family.

## Proof obligations

These are behavioural, not call-count assertions:

- idle session worker at the leased directory stopped; its session reopens cold after the archive;
- stateless worker at the directory stopped; usage worker at its state directory untouched by path;
- busy session (`RUN_ACTIVE`) and busy stateless (`COMMAND_IN_FLIGHT`) refusals; earlier stopped workers stay stopped and their sessions reopen cold;
- acquire racing an in-flight start (delay `prepareBootstrap` through the existing test hook): either the worker is in `workerEntries` and stopped, or its pre-spawn check refuses; no removal and no ref;
- session and stateless starts refused during a lease; allowed after release;
- same/ancestor/descendant lease refused with the holder named;
- service crash during a held archive: no new generation until `resumeRestarts`, then one `start(true)`;
- IPC disconnect stops the service;
- archive refusal leaves neither a ref nor a removed folder; success removes folder and keeps branch;
- removal failure intact: ref deleted and original error rethrown; partly deleted: ref kept and `WORKTREE_ARCHIVE_PARTIAL`, both proved deterministically by the PATH/`OPENCHAMBER_GIT_BINARY` shim above, not a busy-file race;
- restore into a checkout the test created; conflicts stay in the checkout; refusal keeps the archive;
- a release that arrives while acquire is paused in canonicalization cancels that request; after canonicalization resumes, its 409 leaves no admission fence and the same id can acquire again;
- A duplicate acquire during canonicalization is refused without cancelling or releasing the first request's lease; that owner still fences starts until its own DELETE.
- Host validates bound session scope and archive revision at each mutation; moved or foreign sessions remain untouched, including after cache reset and Host restart.
- The web Git adapter exposes archive/list/restore/delete; branch deletion defaults to keep.
- `WORKTREE_ARCHIVE_PARTIAL` rolls back only newly archived sessions at the Host, without a second client rollback.
- delete branch in use refused.

### Corrections to the earlier plan (B1-B6)

- **B1 fence/start race.** The earlier "no worker start is possible inside a lease ... closed by construction" and reliance on per-root `withRoot` were wrong. Canonicalization may await outside the lease-mutation chain; inside the chain, the overlap check, fence install and `workerEntries` snapshot are one synchronous block. `admit` refuses fast, and `launch` rechecks at the last synchronous point before `spawn` for all three start kinds. A failed acquire removes the fence and is safe to release.
- **B2 all worker kinds.** The earlier "stateless and usage ... excluded by kind" and "same guarded stop as `evict`" were wrong. Acquire enumerates session, stateless and usage entries by `cwd`, uses per-kind guards, never uses `evict` for non-session entries, and proves stop success by entry removal plus process-tree exit, with the Windows limit recorded.
- **B3 lease lifetime.** The earlier 60 s TTL was unsafe (snapshot plus removal can exceed it) and did not stop a fresh service generation. The plan deletes it and adds the Host supervisor refcount hold, respecting `scheduleRestart`/`start(true)` without consuming attempts, plus the post-handshake IPC disconnect stop. The Host generates the lease id before acquire and releases that known id even when the 201 is lost; no durable marker, reconcile route or replay.
- **B4 removal failure.** The earlier "a failed snapshot or removal deletes the ref it wrote" could destroy the only copy. The plan adopts upstream's bootstrap wait/status check before snapshot, the intact check before ref deletion, and keeping the ref with `WORKTREE_ARCHIVE_PARTIAL` when the folder was partly deleted; `PARTIAL` is mapped explicitly, the route never resolves 200 when the folder was not removed, and the failure proof is deterministic through a fake `git worktree remove` shim rather than a busy-file race.
- **B5 restore contract.** The earlier interface, Check, and Done-when said that restore creates a checkout at `record.path`. The plan adopts upstream's caller-created checkout shape, updates the route/Check/UI sequence, and states the client must restore before reopening sessions.
- **B6 overlap.** The earlier "the client archives one worktree at a time" is deleted. The overlap decision runs inside the lease-mutation chain after canonicalization, so two concurrently canonicalized requests cannot both pass; it refuses same/ancestor/descendant canonical directories with segment-safe containment and names the holder. The upstream same-path in-flight set is only a local pre-check.

#### Host authority and operation contract

- `createCanonicalSessionService` in `openchamber-sessions/routes.js` owns archive-origin session mutations, invoked by existing Git routes through `index.js` and `feature-routes-runtime.js`. Host SQLite migration version 2 stores one binding keyed by `(hostProjectId, archiveId)` with exact ref/commit, metadata project ID, canonical anchor workspace, phase/revision/claim, target, recovery fingerprints and a durable per-pinned-target automatic apply-attempt intent; per-session rows retain root, workspace, agent-directory, original archive state and progress. `hostProjectId` is not session `projectId`.
- The Host derives every admitted session under the canonical checkout, including nested workspaces, absent UI-cache entries and already archived sessions. Bind all rows transactionally; exact replay is idempotent, but a conflicting key, ref, commit or scope is refused. Host revalidates current scope and archive revision at the actual write owner. Git ref fields and caller paths are never authority.
- The same Host store owns a checkout-scope claim fencing `ensureWorkspace`, `bindSession`, registration/discovery and generic session mutations. Source and pinned restore target remain fenced across live claims and nonterminal phases even after claim release or restart; only the matching internal operation may advance. Before removal, compare the complete Host-derived set with the binding. Completed PARTIAL rollback releases the source for ordinary use. No Agent Service lease expansion or TTL.
- Create the snapshot ref, then bind Host scope and archive originally active sessions before removal. An intact failure restores those newly archived sessions and compare-deletes the exact ref; PARTIAL restores those sessions but retains ref and binding. Already archived timestamps never change. Session rollback belongs only to Host.
- For restore, persist the target, preapply HEAD and complete preimage/result fingerprints in Host SQLite before target mutation. A detached operation-private linked worktree at pinned HEAD reconstructs the target preimage, verifies it, and runs the existing `cherry-pick --no-commit` and reset-on-success/conflict-index behavior. Fingerprints include HEAD, temporary-index `read-tree`/`add -A`/`write-tree`, exact `ls-files --stage -z`, unmerged stages and porcelain-v2 status. If reconstruction cannot be proved, refuse before target mutation and clean up temporary worktree/index. The external probe demonstrates only clean/conflict fixture feasibility, not production or resource proof. Persist the per-target automatic apply-attempt intent durably before invoking Git on the real target.
- Same-target recovery compares complete Host-persisted preimage and expected-result tuples. Exact expected result resumes without reapply. Exact preimage permits one automatic apply only when the durable intent proves no prior attempt. An attempted apply that still matches preimage is ambiguous, including a crash after recording intent but before invoking Git; it never triggers automatic reapply. Ambiguity preserves target, snapshot and binding. The existing restore route exposes explicit confirmed recovery in a new checkout at the persisted preapply HEAD only before any session move/unarchive, with expected revision and target re-pinning. No mutable Git receipt authorizes completion, no implicit target change and no cross-store exactly-once claim.

Failures keep ref and binding for retry. Delete only currently archived sessions whose captured scope and archive version still match and which are not associated elsewhere; persist per-session completion so retry never deletes a moved, unarchived or already-deleted session twice.
