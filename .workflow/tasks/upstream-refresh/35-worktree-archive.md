## Interfaces

### Archive routes

Host, all under `registerGitRoutes` and behind the existing lazy `getGitLibraries()` import:

- `GET /api/git/worktrees/archives?directory=<any checkout of the project>` → 200 `{ archives: Archive[] }`, newest `archivedAt` first. 400 `{ error: 'directory parameter is required' }` without the query.
- `POST /api/git/worktrees/archives?directory=<project>`, body `{ directory: <worktree path>, id, sessionIds?, title? }` → 200 `Archive`; `userAction`.
- `POST /api/git/worktrees/archives/restore?directory=<new checkout>`, body `{ id }` → 200 `{ id, conflicts }`; `userAction`. `directory` is the checkout the caller has already created on the archive's branch (or on the archive's head commit when that branch is gone), exactly as upstream's route and test use it. It is never the project directory and never `Archive.path`.
- `DELETE /api/git/worktrees/archives?directory=<project>`, body `{ id, deleteBranch? }` → 200 `{ id, branchDeleted }`; `userAction`.
- Status policy: 400 for a missing `directory` (query or body), a directory that does not resolve, or an archive id that already exists; 404 `WORKTREE_ARCHIVE_NOT_FOUND`; 409 `WORKTREE_ARCHIVE_IN_PROGRESS`, `WORKTREE_ARCHIVE_NOT_APPLIED` and `WORKTREE_ARCHIVE_PARTIAL` (the fork maps the upstream fall-through explicitly, because the folder is partly deleted and the ref is kept); 409 `RUN_ACTIVE` and `COMMAND_IN_FLIGHT` relayed from the supervisor with its code and the session or lease it names; 501 `{ error: 'Worktree bootstrap storage is not available' }` when the injected `worktreeBootstrapStore.remove` is missing and 501 `{ error: 'Worker lifecycle control is not available' }` when the lease-control hook is missing — both before any git or filesystem change; 503 `SERVICE_UNAVAILABLE` when the Agent Service cannot be reached or does not answer the lease; 500 only for an unexpected local failure. Only the 500 branch logs.
- The route never resolves 200 when the folder was not removed, because the client's `archiveSessionsThenRemoveWorktree` restores the sessions it archived only when the call rejects or `removed === false`.

`Archive` is the record read from the snapshot commit's message: `{ id, ref, commit, head, path, branch, title, archivedAt, sessionIds, branchExists }`. `path` is informational: nothing creates a checkout at it. `sessionIds` is record metadata only; it is never used to decide which workers to stop. The route passes it through the adopted string filter (non-strings dropped, `title` is a string), and adds no second validator or authority.

### Worker lease (Agent Service, internal and SDK-private)

Two private supervisor routes beside `/internal/workers`, reachable only by the Host through its existing `service.request` client, never by the UI or an SDK caller:

```
POST /internal/worktree-leases      { directory: <absolute path> }
  201 { leaseId, released: [rootSessionId, ...] }
  400 INVALID_REQUEST      the directory is relative or empty
  409 RUN_ACTIVE           a session worker at that directory has an active run; details { sessionId }
  409 COMMAND_IN_FLIGHT    a worker there is starting, has pending operations or actions, has a
                           running shell job, holds a restart reservation, or has session storage
                           inside the directory; details { sessionId }
  409 COMMAND_IN_FLIGHT    the directory overlaps an existing lease, same path, ancestor or
                           descendant; details { leaseId, directory }
DELETE /internal/worktree-leases/:leaseId      -> 204, idempotent
```

Lease record: `{ token, canonicalDirectory, state: 'acquiring' | 'active', released: string[] }`. Leases live in Agent Service memory only. One lease-mutation chain serializes acquire and release; no TTL, no persisted marker, no reconcile route and no replay. `released` names the stopped entries for diagnostics (session roots, workspace roots and the usage worker id); it is not an authority the Host may use to decide anything.

Acquire is the release, in this order:

1. Validate that the directory is absolute and canonicalize it (`realpath`, the same convention the Host uses for bootstraps and `removeWorktree` uses at `service.js:5919`). Reject a directory that is the same as, an ancestor of, or a descendant of an existing lease with 409 `COMMAND_IN_FLIGHT` and `details { leaseId, directory }`. Containment is segment-safe (`path.relative` plus `sep`; never a string prefix), matching `isInsideOrSameDirectory` at `service.js:624-627`.
2. Under the lease-mutation chain, install the fence synchronously (`state: 'acquiring'` is visible to admission) and, in the same synchronous step with no intervening `await`, snapshot every `workerEntries` entry whose `input.cwd` is that directory or inside it. A start that spawns during the earlier canonicalization is already in `workerEntries` when the fence is installed, so the snapshot sees it; a start that has not spawned yet reaches `launch`'s pre-spawn check after the fence. The fence, not the per-root `withRoot` lock and not `admit` entry, is the synchronization point; `withRoot` serializes one root only.
3. Stop each snapshotted entry through the per-root `withRoot` serialization, with the guards for its kind. Session entries need the `sessionIsIdle` probe, no starting state, no restart reservation, no pending operations or actions and no running shell jobs, with the same re-checks `evict` performs before it stops. Stateless and usage entries need no starting state, no pending operations or actions, and `stopEntry`; `evict` must not be reused for them because it returns `true` immediately for a non-session entry. A session entry whose `sessionsDirectory` or `sessionFile` is inside the leased directory is refused: removing the folder would delete session storage (the Host default agent directory, `~/.omp/agent`, is outside, but the guard covers a configured one).
4. Prove each stop succeeded by the entry being absent from `workerEntries`, the child having exited, and the worker's process group having exited through `waitForWorkerProcessTree(pid)`. Do **not** use `stopEntry`'s boolean: it returns `child.exitCode === 0`, which is false for a normally SIGTERM-terminated worker. `stopEntry` itself calls `waitForWorkerProcessTree` only when group signalling succeeded, so the lease calls it again. On Windows the helper returns `true` unconditionally; the lease records that limit and does not claim group proof there.
5. Mark the lease `active` and return 201 only after every stop has finished. On any refusal, remove the installed fence, create no lease, and return the 409 with the first refusing session. A release call after a failed acquire is safe and idempotent.
6. A refusal can leave earlier idle workers stopped while the caller only unarchives sessions; those sessions reopen cold. There is no pre-probe and no atomic-rollback claim.

Admission: `admit` checks the fence as a fast refusal, and `WorkerRegistry.launch` checks it again at the last synchronous point before `spawn`, with no `await` between the check and the `spawn`. That one check covers `start`, `startStateless` and `startUsage`, including a start already inside `prepareBootstrap`; no pending-start map is required. An in-flight start is therefore either already in `workerEntries` (the acquire snapshot sees it and stops it) or its pre-spawn check sees the fence. Any start or reopen whose `cwd` is inside a leased directory answers 409 `COMMAND_IN_FLIGHT` with `details { leaseId }`.

Release: by token, idempotent, no path required. The Host calls it in a `finally` on every path, including a failed acquire. `DELETE /internal/workers` semantics are unchanged.

No expiry: there is no `capacityPolicy.worktreeLeaseTimeoutMs` and no "an expired lease stops blocking" criterion. A Host-supervisor restart hold (below), not a timer, keeps a crashed service from admitting a new generation while the Host is still archiving. The owner-death cleanup is `process.once('disconnect', stop)` in `agent-service/src/index.ts` after the secret handshake, beside the existing SIGTERM/SIGINT handlers; a hard-killed Host therefore does not leave the detached service and its unrelated workers running. The IPC disconnect is cleanup, not the fence.

### Host supervisor restart hold

`createAgentServiceSupervisor` exposes `holdRestarts()` and `resumeRestarts()` as a refcount, so two concurrent archives cannot let the first release restart under the second. `holdRestarts` clears a pending `restartTimer`; `scheduleRestart` returns early while held **without consuming `restartAttempts`**; `start(fromRestart === true)` also returns while held. `resumeRestarts` drops one hold and, when the count reaches zero and no child exists, calls the existing `start(true)`; no new timer, no persisted file and no new process. A service crash during the archive therefore spawns no new generation until removal is done and the lease is released, then exactly one generation starts. While the service is alive, unrelated sessions are unaffected except by the path-scoped lease; if it crashes, unrelated sessions are down until resume — the outage a crash already causes, extended by the remaining archive time, with no unrelated worker killed.

Composition: `index.js` builds one lease-control object from `hostAgentRuntime.service` — `holdRestarts` before the `POST /internal/worktree-leases`, `release(leaseId)` and `resumeRestarts` in the same `finally`, and `resumeRestarts` when acquire fails — and passes it through the existing `featureRoutesRuntime.registerRoutes` seam into `registerGitRoutes`. Holding before acquire closes the window between the service returning a lease and the Host recording anything. No new Host route, timer, durable marker or second lifecycle path is added.

Old-worker proof needs no persistence: acquire returns only after every worker at or inside the path is gone, and the pre-spawn fence makes a new worker there impossible; if the service then dies, no generation exists to start one. A crash after release is an ordinary service restart with the folder already removed.

Residual: if release itself fails against a live, hung service after removal, the in-memory lease blocks that path until the service restarts. Removal has already succeeded, so nothing is executing under it, and the plan does not add a TTL or a retry loop as the fix.

### Archive service

Service (`packages/web/server/lib/git/service.js`):

- `listWorktreeArchives(directory)`, `archiveWorktree(directory, { directory, id, sessionIds?, title? }, { bootstrapStore, worktreeWorkers })`, `restoreWorktreeArchive(directory, { id })`, `deleteWorktreeArchive(directory, { id, deleteBranch? })`. `directory` is the project for archive/list/delete and the **new checkout** for restore. `worktreeWorkers` is the injected `{ acquire(directory): Promise<{ leaseId, released }>, release(leaseId): Promise<void> }`.
- Archive ids are `^[A-Za-z0-9_-]{1,80}$`; archive, restore and delete validate the id through the adopted `assertWorktreeArchiveId`/`readWorktreeArchive` path, and list skips a message that is not an archive record. The archive is a snapshot commit of the worktree — every change git does not ignore — under `refs/openchamber/archive/<id>`, whose parent is the commit the branch stood on and whose message is `OpenChamber worktree archive` followed by the JSON record; nothing else records an archive, so the repository is the list.
- Order of an archive: acquire the lease (nothing on disk is touched before it), wait for the active worktree bootstrap and refuse `WORKTREE_BOOTSTRAP_FAILED` before snapshotting, snapshot and write the ref, remove the worktree the way `removeWorktree` removes it while keeping its branch, and release the lease in a `finally`. The bootstrap wait comes before the snapshot because a snapshot taken while setup files are still landing records spurious deletions that a restore would apply.
- Removal failure is handled as upstream handles it, not by deleting the ref unconditionally: `git worktree remove --force` deletes files before it gives up, so after a failure the code reads the snapshot tree and deletes the ref **only when the worktree is provably intact** — still on disk, still registered, and its current state tree equal to the snapshot tree — then rethrows the original error. Otherwise it keeps the ref and throws `WORKTREE_ARCHIVE_PARTIAL`. A worktree can therefore be both partly on disk and archived; the plan does not claim otherwise. The client restores its archived sessions on either refusal because the route rejects.
- The primary workspace, a stray directory, a worktree that never finished setup and a second archive of the same path (the upstream `worktreeArchivesInFlight` same-path pre-check) are refused. Overlap with another lease is refused by the lease, not by this local set.
- Restoring does not create a checkout and never creates one at `record.path`. It takes the caller-created checkout, waits for its bootstrap and refuses `WORKTREE_BOOTSTRAP_FAILED`, applies the snapshot over commits the branch gained after archiving, leaves conflicts in the checkout (which then holds the changes), and drops the archive. When git refuses the apply, the archive is kept and the call fails with `WORKTREE_ARCHIVE_NOT_APPLIED`. `path` from the record is never used as a checkout destination.
- Restoring writes into the new checkout with no lease. The client restores before reopening any session there; a worker must not observe or race the `cherry-pick`/`reset`. This is a client ordering requirement, not a new supervisor route.
- Deleting removes the ref and, when asked, the branch — never a branch a checkout uses.

Boundary: `/api/git/worktrees` is already an entry in `REFUSED_ACROSS_BOUNDARY_ROUTES` and the matcher treats entries as prefixes, so `/api/git/worktrees/archives` and `.../restore` are refused across a space boundary without a new rule; the dispatcher test proves both, and `packages/web/server/lib/spaces/DOCUMENTATION.md` lists the archive routes with that family.

## Proof obligations

These are behavioural, not call-count assertions:

- idle session worker at the leased directory stopped; its session reopens cold after the archive;
- stateless worker at the directory stopped; usage worker at its state directory untouched by path;
- busy session (`RUN_ACTIVE`) and busy stateless (`COMMAND_IN_FLIGHT`) refusals; earlier stopped workers stay stopped and their sessions reopen cold;
- acquire racing an in-flight start (delay `prepareBootstrap` through the existing test hook): either the worker is in `workerEntries` and stopped, or its pre-spawn check refuses; no removal and no ref;
- session and stateless starts refused during a lease; allowed after release;
- same/ancestor/descendant lease refused with the holder named;
- service crash during a held archive: no new generation until `resumeRestarts`, then one `start(true)`;
- IPC disconnect stops the service;
- archive refusal leaves neither a ref nor a removed folder; success removes folder and keeps branch;

### Corrections to the earlier plan (B1-B6)

- **B1 fence/start race.** The earlier "no worker start is possible inside a lease ... closed by construction" and reliance on per-root `withRoot` were wrong. The fence is installed synchronously and snapshotted in the same step, `admit` refuses fast, and `launch` rechecks at the last synchronous point before `spawn` for all three start kinds. A failed acquire removes the fence and is safe to release.
- **B2 all worker kinds.** The earlier "stateless and usage ... excluded by kind" and "same guarded stop as `evict`" were wrong. Acquire enumerates session, stateless and usage entries by `cwd`, uses per-kind guards, never uses `evict` for non-session entries, and proves stop success by entry removal plus process-tree exit, with the Windows limit recorded.
- **B3 lease lifetime.** The earlier 60 s TTL was unsafe (snapshot plus removal can exceed it) and did not stop a fresh service generation. The plan deletes it and adds the Host supervisor refcount hold, respecting `scheduleRestart`/`start(true)` without consuming attempts, plus the post-handshake IPC disconnect stop. No durable marker, reconcile route or replay.
- **B4 removal failure.** The earlier "a failed snapshot or removal deletes the ref it wrote" could destroy the only copy. The plan adopts upstream's bootstrap wait/status check before snapshot, the intact check before ref deletion, and keeping the ref with `WORKTREE_ARCHIVE_PARTIAL` when the folder was partly deleted; `PARTIAL` is mapped explicitly, and the route never resolves 200 when the folder was not removed.
- **B5 restore contract.** The earlier interface, Check, and Done-when said that restore creates a checkout at `record.path`. The plan adopts upstream's caller-created checkout shape, updates the route/Check/UI sequence, and states the client must restore before reopening sessions.
- **B6 overlap.** The earlier "the client archives one worktree at a time" is deleted. The lease set refuses same/ancestor/descendant canonical directories with segment-safe containment and names the holder; the upstream same-path in-flight set is only a local pre-check.

### Recorded limits and bounded decisions

- No optional pre-probe before stopping: a refusal can leave earlier idle workers stopped, and those sessions reopen cold. No atomic-rollback claim.
- No arbitrary new API validators, retry loops, durable leases or framework. Archive ids use the adopted validation on every mutation; `sessionIds` and `title` remain record metadata in the adopted string filter, never authority. A duplicate id is a local 400 refusal, not an unlogged 500.
- No TTL, persisted marker, reconcile route or replay. The lease lives in service memory; the supervisor hold and the IPC disconnect cover the lifetime.
- A release failure against a live, hung service leaves the in-memory lease blocking that path until the service restarts; removal has already succeeded. No retry loop or expiry timer is added.
- `sessionsDirectory`/`sessionFile` are guarded at acquire; the default Host agent directory is outside a worktree, but the optional bootstrap fields make the guard necessary.
- The lease covers OMP workers only; no PTY/editor/language-server quiescence claim. Such a process stays the existing `removeWorktree` busy/retry error.
- The Windows process-tree proof is limited: `waitForWorkerProcessTree` returns true unconditionally, so the lease claims child exit and entry removal there, not group proof.
- A worktree can be both partly on disk and archived after a partial removal; the archive is kept so the data can be restored.
