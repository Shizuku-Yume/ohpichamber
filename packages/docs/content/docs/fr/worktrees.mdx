# Sessions worktree

Une session worktree s’exécute dans sa propre copie extraite de votre dépôt, sur sa propre branche (un git worktree). Les sessions parallèles ne se marchent donc pas sur les fichiers — l’une peut refactorer pendant qu’une autre corrige un bug, sans allers-retours constants.

## En créer une

1. Ouvrez la boîte de dialogue nouveau worktree : choisissez **Nouveau worktree…** dans le menu des branches au-dessus du champ de saisie quand vous démarrez une session, ou utilisez le bouton worktree sur la ligne d'un projet dans la barre latérale.
2. Sous **Start from**, choisissez une option :
   - **new branch** — nommez la branche
   - **existing branch** — récupérez une branche que vous avez déjà
   - **PR or issue** — choisissez-en un depuis GitHub, GitLab, Gitea, Forgejo, Gerrit, Linear ou une extension ; la branche prend son nom (une PR récupère sa propre branche, un changement Gerrit son dernier patchset sur `change-<number>`) et l'élément est joint à votre premier message
3. Vérifiez **Based on** (la branche de départ d'une nouvelle branche, par défaut la branche par défaut du dépôt distant, par exemple `origin/main`) et **Folder name** ; ne les modifiez que si nécessaire.
4. Créez-le. Si le projet a des commandes de configuration, elles s'exécutent juste après.

OpenChamber crée la branche, prépare le dossier et y ouvre une nouvelle session, prête pour votre premier message. Vous pouvez aussi en lancer une directement depuis une [todo](/notes-todos-plans/) ou une [issue ou pull request](/github/).

Pour éviter les questions, choisissez **Worktree rapide** dans le même menu : OpenChamber donne à la branche un nom provisoire et y place la nouvelle session. Une fois que l’agent a nommé la tâche, il renomme aussi la branche d’après elle, par exemple `fix/login-timeout`, tant que la branche n’a pas encore été poussée.

## Dans la barre latérale

Un worktree occupe une ligne dans la barre latérale, avec toutes ses sessions dessous. Sous son projet, il est classé parmi les autres sessions du projet selon sa dernière activité : un worktree où vous venez de travailler se trouve donc près du haut. La ligne affiche le nom de la tâche dès que l’agent l’a nommée (avant cela, le titre de la dernière session où vous y avez travaillé), la pull request ou l’issue qu’il suit sous forme de marque colorée, et si une session y tourne ou a du nouveau pour vous. Un worktree créé pour une pull request ou une issue porte d’abord le titre de cet élément, jusqu’à ce que l’agent choisisse un nom plus court. Survolez-la pour voir la branche. Cliquez dessus pour ouvrir la dernière session où vous y avez travaillé ; pour déplier la liste, survolez l’icône de branche à sa gauche et cliquez sur la flèche qui prend sa place. Son menu renomme la tâche, range le worktree dans un dossier du projet, l’archive ou le supprime. Sur le téléphone, touchez la flèche de la ligne pour déplier la liste, et faites glisser la ligne sur le côté pour la marquer comme terminée, renommer la tâche, archiver le worktree ou le supprimer. Voir [Sessions en cours](/fr/sessions-in-work/) pour savoir comment les travaux entrent dans le bloc En cours et en sortent.

## Projets ouverts sur un dossier du dépôt

Si vous ouvrez un projet sur un dossier à l'intérieur d'un dépôt, comme `repo/ai`, les nouveaux worktrees s'ouvrent aussi à cet endroit. Une session dans un nouveau worktree démarre dans le même dossier du checkout, et l'agent trouve ainsi la configuration qui s'y trouve. Un projet ouvert à la racine du dépôt démarre à la racine du worktree, comme avant. Si une branche n'a pas ce dossier, la session démarre à la racine du worktree et OpenChamber vous le signale.

## Ramener le travail

Quand le travail est bon, utilisez **Integrate** dans la vue Git pour ramener les commits du worktree sur une autre branche (comme `main`). Si un changement entre en conflit, vous pouvez confier la résolution du conflit à l’agent.

## Nettoyer et archiver

Quand la tâche est terminée, choisissez **Archiver le worktree** dans le menu de la ligne, ou maintenez la touche Shift enfoncée et cliquez sur le bouton d’archivage qui prend la place du bouton de nouvelle session sur la ligne. OpenChamber l’archive :

1. Le Host vérifie le worktree et l’isole, libérant chaque worker actif qui retient le répertoire et empêchant toute nouvelle commande d’aboutir pendant l’archivage.
2. Les modifications non commitées et l’état des branches sont enregistrés dans des références de capture sous `refs/openchamber/archive/<id>`.
3. Le dossier est supprimé du disque en toute sécurité tout en préservant la branche Git, la capture non commitée et les enregistrements de session associés.
4. Si une session dans le worktree est activement en cours de streaming ou d’exécution, l’opération d’archivage est refusée en toute sécurité jusqu’à ce que l’exécution soit terminée.

Marquer une ligne de worktree comme terminée la retire uniquement du bloc **En cours**. Pour archiver automatiquement un worktree chaque fois que vous le marquez comme terminé, ou une fois sa pull request fusionnée, activez **Paramètres → Sessions → Worktrees terminés**.

### Restaurer depuis les archives

La page **Archives** répertorie les worktrees archivés sous leurs projets respectifs :

- **Restaurer :** Réintègre le worktree archivé dans un checkout créé par l’appelant (`openchamber/worktree-...`). Le Host restaure les fichiers non commités à partir de la référence de capture, réapplique les commandes de configuration du projet et replace les sessions actives dans le nouvel emplacement de checkout.
- **Préservation de l’état de session :** Les sessions actives vérifiées par le Host s’ouvrent à nouveau dans le worktree restauré une fois les modifications intégrées. Les sessions qui étaient déjà archivées avant l’archivage du worktree restent archivées dans la liste des archives. Les fichiers ignorés par Git (comme `node_modules` ou `.env`) sont recréés par les commandes de configuration du projet.
- **Récupération confirmée dans un nouveau checkout :** Le flux de récupération s’assure automatiquement que le nouveau répertoire de checkout est admis dans le périmètre d’espace de travail du Host avant de rouvrir les sessions.

### Supprimer des worktrees et sécurité des branches

Pour supprimer définitivement un worktree :

- **Depuis la barre latérale active :** Choisissez **Supprimer** dans le menu de la ligne du worktree.
- **Depuis la page Archives :** Cliquez sur **Supprimer** sur la ligne d’un worktree archivé.
- **Conservation de la branche par défaut :** La suppression d’un worktree archivé conserve par défaut la branche Git et son historique de commits. La boîte de dialogue de confirmation de suppression fournit une case à cocher explicite **Supprimer aussi la branche locale**, décochée par défaut.
- **Anciennes archives sans liaison réservées à Git :** Les références de capture plus anciennes dépourvues de liaisons d’état de session détenues par le Host n’autorisent qu’une récupération Git pure. OpenChamber avertit explicitement que les sessions associées ne seront pas déplacées, désarchivées ou supprimées. Supprimer une archive non liée nécessite une confirmation explicite pour supprimer une branche non vérifiée.

## Si quelque chose semble étrange

Un worktree peut demander votre attention si son dossier a disparu, si sa branche est détachée, ou si un merge ou rebase est à moitié terminé. OpenChamber signale ces cas pour que vous puissiez les corriger — voir [Worktrees et Git](/troubleshooting/worktrees-git/).
