Read [DESIGN.md](DESIGN.md) first.

## Local status and upstream provenance

The assembled source now includes tools/gatekeeper infrastructure, code transfer, dispatcher, journey UI, dev preview and OpenAI credential integration. The current owning contract is [the spaces module documentation](../../packages/web/server/lib/spaces/DOCUMENTATION.md). `ISOLATED_SPACES_RELEASED` remains false; the release-hidden UI and manual `isolatedSpacesEnabled` host setting are different gates.

The table below preserves dated upstream experiments and delivery obligations. Its recorded live results were not rerun here. No Docker CLI/daemon is available in this environment, so containment, code transfer/apply, credential use and full journey acceptance remain blocked. OMP runtime, auth and event mapping must be verified before the later cutover; imported source passes no sandbox gate.


## Delivery rules

- Deliver each local change as a focused workflow task. If a stage grows, split it into independently verifiable tasks. Follow `.workflow/standards.md` for landing rather than the inherited upstream pull-request ceremony.
- The whole feature stays behind one switch. While the switch is off, the server registers none of the feature's routes, the UI shows none of its entry points, and nothing of the feature runs at all: see decisions 17 to 19 in [DESIGN.md](DESIGN.md). The switch gates the work while it is built, and at the first release it becomes the user's opt-in in Settings rather than being removed. The stage that builds the feature's settings screens builds it.
- Before completing a boundary-changing task: run every applicable escape test that exists so far and complete the stage checklist from [TESTING.md](TESTING.md).
- A checklist line has two states: "passed, here is the evidence" or "blocked, here is the reason". There is no "skipped".
- Use the active workflow task for evidence and review. A completed document move does not count as a delivered sandbox stage.
- The later OMP implementation of Stage 4 uses the canonical contract through the Host Gateway after capability verification. This is a final migration requirement, not a prohibition on inheriting upstream's existing dispatcher/events during the prerequisite rebaseline. Source import alone passes no sandbox boundary check.

The contract test suite is written in stage 1 and stays fixed against being rewritten per place. It is not frozen against a new stage: stage 2 added three assertions to it and changed none of the existing ones. The three are that the gatekeeper target runs in a container of its own, that `exec` knows those two targets and rejects any other, and that the gatekeeper is gone after `remove`. Each of them is marked in the file, and each was confirmed to fail against a place that fakes a gatekeeper. From stage 2 on, a place cannot host a space without a gatekeeper, so every later place is held to that too. A later place is done only when it passes the whole suite, including every escape test.

The Linux listener-exposure finding from stage 2 is historical. Stage 5b chose the inner-network-only bind file. The current program rejects a missing, empty or wildcard bind address; the module contract's “Known limits” records the mechanism and dated Linux measurement. Re-run outer-network and host attempts alongside an authorized credential operation on real Docker before claiming the fork closes this boundary.

Carried stage 2 obligations, reconciled with the adopted source:

- Grants and the allowlist remain gatekeeper memory. The journey now restores network policy, environment-source grants and credential-free domain grants after start. Typed secrets are not persisted and cannot be restored. The access projection distinguishes missing grants from a failed policy read; verify restart and “needs access” transitions live.
- The journal is memory only too. The blocked-attempts view shows nothing from before the gatekeeper last started, and it has to say so. An empty list that means "the record is gone" must not read as "the agent tried nothing".
- Turning the switch off stops every space and keeps its files, and the banner beside the switch has to say so before the user commits, with the count. Removing spaces is a separate action offered after the switch is off, never a checkbox beside the toggle: see decision 18. A space that could not be stopped is reported as still running.
- The current grant API accepts model credentials and credential-free domain grants. The window strips inbound credential headers for both. Adding a domain to the corridor allowlist is a separate operation; it does not bypass private-address restrictions. Private npm metadata and tarball downloads through an authorized window remain unverified; establish absolute-URL behavior before choosing registry rewriting.
- A removed gatekeeper is still not recreated by `start`. The current list reports `damage: 'gatekeeper_gone'`; verify the repair/discard UI rather than treating source presence as recovery evidence.

Later, in no fixed order: project-defined images, submodules, sandbox services, Copilot through the gatekeeper.
